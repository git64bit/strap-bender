Batch 022 implements:
 - Catalog-ready object contract version 1;
 - manufacturing/export manifest contract version 1;
 - a complete embedded recipe payload containing the normalized bend program,
   exact strap-material record, cut policy, fixture specification, layout mode,
   setup-aid specification, revision, source provenance, and lifecycle state;
 - explicit lifecycle states laboratory_candidate and accepted;
 - candidate validation that forbids physical acceptance date/notes;
 - accepted-state validation that requires source-commit, acceptance-date, and
   physical-acceptance-note provenance;
 - deterministic regeneration of analytical path, nominal cut plan, fixture
   plan, clearance analysis, optional segmentation, and setup aids from the
   embedded recipe;
 - deterministic zero-padded fixture component export identities;
 - deterministic per-component SCAD recipe and STL filenames;
 - deterministic object-recipe and manufacturing-manifest filenames;
 - one export entry for a full-form fixture or one entry per existing segmented
   fixture component;
 - exact station intervals and component base bounds in each export entry;
 - a reportable manufacturing manifest that includes nominal cut length,
   fixture layout, and the complete printable-component export list;
 - independent Manufacturing package controls in Bend Program, Vertex Polygon,
   Regular Polygon, and Wave Pattern workbenches;
 - material routing for manufacturing packaging independent of cut-plan display
   and fixture rendering;
 - preservation of original authoring kind/name while the normalized bend
   program remains the embedded geometry source of truth;
 - api/v1.scad as the first explicit versioned immutable-object renderer;
 - objects/README.md defining immutable accepted-object/component recipe rules;
 - direct-open contracts for the public API, Catalog-ready object semantics,
   deterministic full/segmented manifests, and workbench routing;
 - public-foundation coverage for the new records and planning layer.

Important Batch 022 boundary:
 This batch creates application machinery for Catalog-ready packaging, but it
 does NOT create or register a physically accepted Strap Bender object.
 registries/catalog_projects.scad remains the existing Catalog stub. Synthetic
 accepted-state records exist only inside contract tests and are explicitly
 labeled as synthetic.

OpenSCAD does not automatically write SCAD, STL, text-manifest, or 3MF files.
 The manifest deterministically reports the required filenames and component
 indexes. STL export remains an explicit user action from the corresponding
 immutable component recipe or workbench component selection. Slicer-only state
 remains an external manufacturing-project reference.

This batch deliberately does NOT add:
 - a physical Catalog registration;
 - empirical target-to-tool radius compensation;
 - calibrated neutral-axis or K-factor fitting;
 - empirical cut-length correction;
 - automatic promotion from Laboratory candidate to accepted Catalog object;
 - automatic filesystem writes from OpenSCAD;
 - strap-solid visualization.
